## 一、实验实现

本实验为 easy-fs 的 DiskInode 增加 nlink 字段，并把 INODE_DIRECT_COUNT 从 28 改为 27，以保持 inode 仍为 128 字节。实现 linkat：在目录末尾追加指向原 inode 的目录项，并把原 inode 的 nlink 加一；实现 unlinkat：删除目录项并递减 nlink，减至 0 时释放数据块和 inode；实现 fstat：返回设备号、inode 编号、文件类型和链接数，并逐页拷贝回用户空间。重建镜像后 ch6_file1/2/3 均通过，ch6_usertest 全部测例通过。

## 二、问答作业

### 在我们的 easy-fs 中，root inode 起着什么作用？如果 root inode 中的内容损坏了，会发生什么？

**答：** root inode 是 easy-fs 的根目录 inode（inode 编号 0），是整个文件系统的入口。`EasyFileSystem::root_inode()` 通过 `get_disk_inode_pos(0)` 定位它，内核首次访问文件系统时把它封装成 `ROOT_INODE`，之后所有路径解析（open/create/link/unlink/exec）都从 `ROOT_INODE.find(name)` 开始。它的类型是 Directory，其数据块中存放根目录的目录项（文件名 → inode 编号）；easy-fs 不支持子目录，所以它是唯一的目录，所有文件都由它的目录项直接索引。

如果 root inode 的内容损坏：若 inode 元数据（size/direct/indirect/type）损坏，`find_inode_id` 会按错误的 size 和块号解析目录项，得到错误的 inode 编号，甚至触发 panic（非法块号、非法 UTF-8、断言失败等），导致所有路径都无法解析，整个文件系统不可用；若只是部分目录项损坏，未损坏的名字仍可访问，损坏项会指向错误的 inode，而原文件对应的 inode 和数据块可能仍然完好，但已没有任何目录项指向它们（成为孤儿），位图也仍标记为占用、无法回收。easy-fs 没有 fsck、冗余或备份，无法自动恢复，只能重建镜像；而且挂载时只校验超级块 magic，root inode 损坏要到第一次查找时才会暴露。
